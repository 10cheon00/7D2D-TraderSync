# TraderSync

여러 플레이어가 같은 NPC 상인의 거래 창을 동시에 열고 거래할 수 있는 7 Days to Die 모드입니다. 거래 창은 공유 잠금을 사용하고, 구매·판매는 서버에서 순서대로 확정합니다. 자동판매기는 기존 게임의 거래 방식을 유지합니다.

## 빌드 및 설치

.NET SDK와 .NET Framework 4.8 Developer Pack이 필요합니다. 게임의 `Assembly-CSharp`, `UnityEngine.CoreModule`, `LogLibrary`, `Mods/0_TFP_Harmony/0Harmony`를 직접 참조합니다.

```powershell
dotnet build TraderSync.csproj -c Release
# 다른 게임 설치 경로
dotnet build TraderSync.csproj -c Release -p:GamePath="D:\SteamLibrary\steamapps\common\7 Days To Die"
```

`bin/Release/net48/TraderSync.dll`과 `ModInfo.xml`을 서버와 모든 클라이언트의 `Mods/TraderSync`에 복사합니다. EAC를 끄고 게임의 `0_TFP_Harmony`를 유지합니다. 서로 같은 버전이 필요하며 게임 시작 로그에 `server transactions and live stock propagation enabled`가 표시됩니다. `src`만 컴파일하므로 `Analysis`의 디컴파일 코드는 배포에 포함되지 않습니다.

## 거래 처리

1. `TraderViewers`가 상인 ID별로 거래 채널 잠금을 획득한 플레이어 ID 집합을 관리합니다.
2. 구매/판매의 `OnActivated`를 가로채 로컬 즉시 매매를 중지합니다. 현재 인벤토리 업로드 후 동일한 신뢰성 있는 채널로 거래 요청을 전송합니다. 요청에는 연결 내 증가하는 번호, 상인·품목·슬롯·수량·표시 가격과 재고/인벤토리 해시가 들어갑니다.
3. `TradeServer`와 `TransactionLedger`가 검증부터 반영까지 하나의 서버 임계구역에서 실행합니다. 현재 구현은 상인별 잠금보다 강한 서버 전체 거래 직렬화를 사용합니다. Unity 게임 객체 작업은 게임 스레드에서 실행하며 작업자 스레드를 만들지 않습니다.
4. 서버는 거래 권한, 영업 상태, 재고·인벤토리·품목 일치, 수량, 서버 계산 가격, 돈, 공간, 매입 한도를 검사합니다. 상인 재고 및 배낭/도구벨트의 복사본에서 먼저 정산합니다. 검증·정산 실패 시 원본은 변경하지 않습니다.
5. 성공한 복사본을 상인과 `ClientInfo.latestPlayerData`에 반영합니다. 호스트도 같은 처리기를 사용합니다. 구매 품목/잔액 변경과 판매 품목/대금 변경을 함께 반영하고, 거래자는 응답에서 확정 인벤토리를 적용합니다.
6. 확정 재고는 요청자를 포함한 열람자들에게 전파됩니다. 응답 재전송 시에도 최신 재고는 별도로 전송하므로 과거 결과의 재고를 덮어쓰지 않습니다.
7. 응답을 적용한 클라이언트가 ACK를 보내면 다음 거래와 일반 인벤토리 업로드를 허용합니다. 응답 대기 중 도착하는 이전 배낭/도구벨트 및 플레이어 저장 데이터는 확정 인벤토리를 덮어쓸 수 없습니다.

### 충돌과 재전송

- 같은 마지막 상품을 두 명이 요청하면 먼저 확정된 거래만 성공합니다. 뒤의 요청은 재고 해시 불일치로 거절되고 최신 목록을 받습니다. 다른 품목 거래로 재고가 바뀐 경우에도 보수적으로 거절하므로 확인 후 다시 클릭해야 할 수 있습니다.
- 같은 요청 번호는 저장된 결과만 반환합니다. 더 오래된 요청 번호는 재실행하지 않습니다. 타임아웃은 취소로 취급하지 않고 2초마다 같은 요청을 재전송합니다.
- 기존 `NetPackageTraderData`의 NPC 재고 전체 덮어쓰기 및 `TraderData.SetModified`의 NPC 업로드는 차단합니다.
- 거래 대기 중 추가 매매, 기본 슬롯 이동·정렬·아이템 행동·제작 완료/취소를 잠시 막고 거래 창의 일반 닫기를 지연합니다. 사망 시 아이템 드롭과 리스폰은 정산 응답 후 진행합니다.
- 응답 대기 중 게임을 종료하면 종료 시 배낭 드롭은 생략하고 서버의 확정 인벤토리를 유지합니다. 이전 인벤토리를 바닥에 떨군 뒤 정산 결과까지 저장하는 중복을 방지하기 위한 처리입니다.
- 판매 시 장전된 탄약은 배낭/도구벨트에 돌려줍니다. 탄약과 대금을 함께 넣을 공간이 없으면 거래 전체를 거절하며 바닥에 자동으로 버리지 않습니다.
- UI 경험치·퀘스트 알림은 처음 적용한 성공 응답에서만 실행합니다.
- 실시간 재고 갱신은 보고 있던 품목의 상세 정보와 구매 수량을 유지합니다. 품질·내구도·개조·메타데이터가 같은 품목을 다시 찾아 구매 대상 슬롯을 갱신하며, 남은 수량/수용 공간이 줄면 구매 수량만 가능한 범위로 제한합니다. 같은 품목의 동일 스택이 여럿이면 가능한 한 기존 순서의 스택을 사용합니다. 해당 품목이 목록에서 완전히 사라진 경우에만 상세 선택을 해제합니다.
- 삭제로 품목이 다른 페이지로 이동해도 현재 페이지는 그대로 두고 상세 정보의 구매 대상을 유지합니다. 배낭 품목을 보고 있을 때는 그 상세 정보를 건드리지 않습니다.

## 보장 범위

실행 중인 서버의 이 모드 거래 요청 사이에서 직렬 실행, 검증 실패의 무변경, 요청의 중복 정산 방지를 제공합니다. 게임의 일반 플레이어 인벤토리 업로드는 원래 클라이언트 주도 방식이므로 이 모드가 전체 게임을 서버 권위 인벤토리 시스템으로 바꾸는 것은 아닙니다.

DB의 WAL이나 분산 트랜잭션 저장소는 구현하지 않았습니다. 서버 강제 종료/크래시 시 상인 저장과 플레이어 저장을 디스크에 원자적으로 복구한다는 보장은 없습니다. 다른 모드가 대기 중인 인벤토리나 상인 데이터를 직접 변경하는 경우에는 별도 통합 검증이 필요합니다. 접속 종료 전에 확정된 거래는 서버의 플레이어 데이터에 남고, 늦은 업로드가 이를 되돌리지 않도록 보호하지만, 응답 전에 종료된 플레이어의 클라이언트 경험치/퀘스트 알림까지 영속적으로 재전달하는 기능은 없습니다.

## 자동 검증

```powershell
dotnet run --project tests/TraderSync.TransactionTests -c Release
dotnet run --project tests/TraderSync.PipelineTests -c Release
dotnet run --project tests/TraderSync.SelectionTests -c Release
```

.NET 10 실행기가 실제 거래 처리·정산·요청 기록·전파 코드와 게임 API 대체 객체를 함께 실행합니다. 거래 테스트는 마지막 상품 동시 구매, 동시 판매 한도, 중복/과거 요청, ACK, 잔액/공간 부족, 가격/인벤토리/품목 불일치, 권한 및 세션 정리를 검증합니다. 전파 테스트는 수신자, 호스트, 직렬화 왕복, 버전 역전, 창 닫기 등을 검증합니다. 대체 객체 테스트는 실제 Harmony 적용, 게임 직렬화/가격 효과 및 Unity UI 검증을 대신하지 않습니다.

## 게임 내 확인 항목

- 전용 서버 및 호스트 환경에서 두 플레이어가 같은 상인을 열고 각각 구매·판매하고 양쪽 목록을 확인합니다.
- 수량 1 상품을 동시에 구매해 한 명만 지급·차감되는지 확인합니다. 뒤의 요청은 최신 재고 확인 안내가 나와야 합니다.
- 같은 상품의 매입 한도 직전에서 동시 판매하고, 잔액 부족/공간 부족에서는 재고·돈·품목 모두 그대로인지 확인합니다.
- 할인 버프/퍽, 품질/내구도, 블록 묶음, 장전 탄약, 특수 재고와 재입고를 확인합니다.
- 지연된 응답, 연속 클릭, 접속 종료/재접속, 거래 중 사망에서 중복 지급·되돌림이 없는지 확인합니다.
- 다른 상인과 자동판매기, 거래 종료 후 목록 제거, 월드 재시작 초기화를 확인합니다.
- 품목 상세 정보(능력치 탭 포함)를 연 채 구매 수량을 지정하고, 다른 플레이어가 구매/판매할 때 상세 정보·수량·검색·분류·페이지가 유지되는지 확인합니다. 앞쪽 품목 삭제로 슬롯/페이지가 바뀌었을 때도 구매가 원래 품목을 대상으로 하는지 확인합니다. 선택한 품목의 수량 감소 및 품절도 확인합니다.
